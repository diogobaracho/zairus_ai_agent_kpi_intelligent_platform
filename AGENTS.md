# AGENTS.md — working agreement for AI coding agents (and humans) in this repository

Tool-agnostic: Claude Code, Codex, Cursor, Copilot and people all follow the same rules. Keep this
file true; when a rule changes, change it here first.

## Non-negotiables

1. **One domain layer.** `packages/kpi_core` owns business logic. `services/api` and
   `services/mcp` are thin adapters; they never contain query or suggestion logic.
   `kpi_core` never imports from `services/` or `apps/`.
2. **The LLM never supplies identity.** `tenant_id`, `principal` and `trace_id` come from
   `RequestContext`, built server-side. Tool schemas must never expose them as parameters.
3. **No raw SQL.** ORM `select()` with bound parameters only. `text(` outside migrations fails
   `scripts/audit_docs.py`. The model never sees SQL.
4. **Errors are structured.** Raise `KpiError` subclasses. REST returns RFC 9457
   `application/problem+json`; MCP returns the JSON envelope via `ToolError`. Never a bare
   `except Exception` that returns a friendly string.
5. **Every tool call is audited.** `tool_call_audit` row + `tool_call` JSON log line with
   `trace_id`, arguments, status, duration, error. No code path may bypass the MCP middleware.
6. **Zero-key default.** `make up` must work with no API keys (stub LLM provider). Never make the
   stub "smarter" than a scripted, deterministic provider.
7. **Synthetic data only.** `data/*.csv` is generated by `scripts/generate_sample_data.py`
   (deterministic). Change the generator, regenerate, and update the tests that count rows.
8. **Docs ship with the code.** A change to a tool, endpoint, env var or error code updates
   `docs/reference/*` in the same commit.

## Layout and import rules

| Path | Package | May import |
|---|---|---|
| `packages/kpi_core` | `kpi_core` | stdlib, pydantic, sqlalchemy, rapidfuzz |
| `services/api` | `kpi_api` | `kpi_core`, fastapi, anthropic (only in `agent/providers/anthropic_provider.py`), fastmcp client |
| `services/mcp` | `kpi_mcp` | `kpi_core`, fastmcp |
| `apps/chat-web`, `apps/website` | TS | nothing from Python; talk to the API over HTTP |

## Commands

`make help` lists everything. Before starting work: `make bootstrap && make ci`. Before
finishing: `make format && make ci`. Postgres tests: `make test-integration`. Full stack:
`make up && make test-e2e`.

## Where things live

- Tool contracts: `services/mcp/src/kpi_mcp/tools.py` + `docs/reference/mcp-tools.md`
  (`make tool-docs` refreshes the JSON snapshot).
- Agent guards: `services/api/src/kpi_api/agent/guards.py` and `loop.py`; system prompt in
  `agent/prompts.py`.
- Error codes: `packages/kpi_core/src/kpi_core/errors.py` + `docs/reference/error-codes.md`.
- Config: `docs/reference/configuration.md` (every `KPI_*` variable).

## Commits

Conventional commits (`feat(scope):`, `fix(scope):`, `docs:`, …), small and focused, body says
*why*. Work on a branch; never push unless asked.

## Traps

- FastMCP middleware: `on_call_tool(context, call_next)`; `ToolError` is the only exception
  whose message reaches the client when `mask_error_details=True`.
- Anthropic SDK: all `tool_result` blocks of one assistant turn go in ONE user message; parse
  tool inputs as JSON; no prefill.
- Starlette `BaseHTTPMiddleware` breaks ContextVar propagation; use pure-ASGI middleware.
- SSE through nginx needs `proxy_buffering off`.
